# Checklist Executor

你正在执行一个原子清单文件。按以下流程操作，不可跳过步骤。

## 流程

### 阶段 0：基线验证（必须最先执行）

清单通常包含一个"当前验证基线"段落。**不要信任清单中声称的状态**——必须实际运行验证命令确认。

```
1. 运行清单中列出的所有基线验证命令
2. 逐项比对实际输出与清单声称的状态
3. 如有偏差，记录在案并调整优先级（已通过的项直接标记完成）
```

常见偏差场景：
- 清单说"ESLint 23 warnings"但实际是 0/0（已在前序会话修复）
- 清单说"test:all 通过"但实际有失败
- 清单说"backend build 通过"但 typecheck 报错

### 阶段 1：分类与执行

按清单的优先级（P0 → P1 → P2 → P3 → P4）逐项执行：

1. 读该项的所有原子任务
2. 读验收标准
3. 执行原子任务
4. 运行该项的验收命令
5. 标记完成

### 阶段 2：收尾验证

所有项完成后，运行完整基线验证命令确认无回归。

## 交付格式

每完成一项，输出：

```
改动文件：
- ...

完成原子项：
- [Px-y] ...

验证：
- 各命令 pass/fail

剩余风险：
- ...
```

## 反模式

- ❌ 跳过基线验证直接执行（清单可能过期）
- ❌ 信任清单中的文件路径而不实际 read_file 确认
- ❌ 在未读组件源码的情况下写测试（label/placeholder 猜测会失败）
