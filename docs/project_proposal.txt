# Todo Pro 项目企划书与开发进度总结

版本：2026-06-01 更新版（加入 Phase 2 domain 层开发、macOS 快捷键工具）

---

## 1. 一句话定位

Todo Pro 是一个"多来源 AI 任务收件箱"：用户把聊天、网页、截图、邮件、PDF 或授权应用中的信息交给它，它先生成可确认的任务草稿，再由用户审核、编辑、保存或同步到常用待办工具。

---

## 2. 用户问题与机会

用户的待办事项分散在微信/聊天、网页、邮件、截图、课程通知、文档和日历信息中，手动复制粘贴成本高。
现有待办工具擅长管理任务，但通常不擅长从复杂上下文中识别任务。
手机系统 AI 助手、Trello、Todoist、Microsoft To Do 等方向有相似能力，但"多格式内容 -> AI 识别 -> 用户确认 -> 同步"的个人任务入口仍有差异化空间。
项目优势应放在用户主动分享/授权、图片 OCR、多格式解析、任务确认卡片和隐私可控上。

---

## 3. 产品原则

- 先做本地闭环，再做 AI、OCR 和同步。
- AI/OCR 输出只作为建议，默认必须经过用户确认。
- 保留来源追踪：每条任务应能解释来自哪段文本、截图或文件。
- 模糊时间必须提示用户确认，例如"下周五""明晚""月底前"。
- 不默认后台读取其他 App；优先使用用户主动分享、粘贴、上传或明确 OAuth 授权。
- 移动端永远不存放 DeepSeek/OpenAI 等模型 API key，统一走后端 provider。
- Todo Pro 必须先成为独立可用的本地 AI 任务备忘录/收件箱，再逐步成为外部 App 的输入源或同步目标。
- 动画必须解释状态变化，不为装饰而装饰；效率工具优先清晰、安静、可信、快速。

---

## 4. 当前技术栈与开发方式

| 模块 | 当前选择 |
|---|---|
| App | Expo + React Native + TypeScript |
| 路由 | Expo Router |
| 本地存储 | AsyncStorage 优先；任务量和查询复杂后再升级 SQLite |
| 日期处理 | `clientTimeParser.ts`（NLP 中文时间解析，245 行）+ `dayjs` |
| AI 接入 | 后端 API provider 层（mock / DeepSeek），移动端不放 key |
| UI/动画 | Liquid Glass 主题系统（4 个预设 + 自定义主题编辑器） |
| OCR | macOS `ocr-claw` 脚本 + 后端 OCR.Space provider |
| 同步 | Firebase / Todoist / Calendar / Reminders 数据结构已就绪 |
| 协作方式 | Claude Code 负责本地代码执行 |

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 过早做 OCR/权限/同步导致复杂度爆炸 | 先完成本地闭环和 review cards |
| AI 误识别任务或时间 | 默认生成草稿，不直接创建正式任务 |
| 隐私争议：自动读取其他应用 | 用户主动分享/上传/授权优先 |
| 移动端泄露 API key | 所有模型请求通过后端 provider |
| 组件继续膨胀 | 中等改动前执行 refactor gate |
| Expo 环境问题 | 优先 `npx expo-doctor`、`npx tsc --noEmit` 排查 |
| 玻璃拟态影响可读性 | 默认高不透明度 glass，优先文字清晰 |
| 动画拖慢效率 | 动画只解释状态变化，时长 160-360ms，尊重 Reduce Motion |
| **Shortcuts sandbox 权限** | 替代方案：Hammerspoon / Raycast / Alfred 调用 |
