Todo Pro 项目企划书与开发进度总结
版本：2026-05-27 更新版（加入本地运行策略与 macOS 26 风格 UI/动画方向）

1. 一句话定位
Todo Pro 是一个“多来源 AI 任务收件箱”：用户把聊天、网页、截图、邮件、PDF 或授权应用中的信息交给它，它先生成可确认的任务草稿，再由用户审核、编辑、保存或同步到常用待办工具。
2. 用户问题与机会
用户的待办事项分散在微信/聊天、网页、邮件、截图、课程通知、文档和日历信息中，手动复制粘贴成本高。
现有待办工具擅长管理任务，但通常不擅长从复杂上下文中识别任务。
手机系统 AI 助手、Trello、Todoist、Microsoft To Do 等方向有相似能力，但“多格式内容 -> AI 识别 -> 用户确认 -> 同步”的个人任务入口仍有差异化空间。
项目优势应放在用户主动分享/授权、图片 OCR、多格式解析、任务确认卡片和隐私可控上。
3. 产品原则
先做本地闭环，再做 AI、OCR 和同步。
AI/OCR 输出只作为建议，默认必须经过用户确认。
保留来源追踪：每条任务应能解释来自哪段文本、截图或文件。
模糊时间必须提示用户确认，例如“下周五”“明晚”“月底前”。
不默认后台读取其他 App；优先使用用户主动分享、粘贴、上传或明确 OAuth 授权。
移动端永远不存放 DeepSeek/OpenAI 等模型 API key，统一走后端 provider。
Todo Pro 必须先成为独立可用的本地 AI 任务备忘录/收件箱，再逐步成为外部 App 的输入源或同步目标。
动画必须解释状态变化，不为装饰而装饰；效率工具优先清晰、安静、可信、快速。

7. 本地运行与外部 App 集成策略
核心决策：Todo Pro 先把识别能力和自己的备忘录/任务收件箱集成在一起，而不是一开始依赖外部 App 接口。

8. UI 与动画设计方向：Vibrant & Bold Liquid Glass UI
Todo Pro 应采用大胆且极具视觉表现力的“极致版 Liquid Glass”审美：极致通透的深层毛玻璃、全沉浸式的光影材质、以及富有张力与生命力的丰富空间层级动画。我们要打造令人惊艳的视觉奇观。
视觉关键词
vibrant
ultra-translucent
immersive
expressive
dynamic
native-feeling
设计原则
Inbox 像柔和的玻璃托盘；Task Draft 像可确认的浮层卡片；Today/Plan 保持稳定清晰。
AI 提取过程应表现为“内容沉淀成任务”，不要做成聊天机器人界面。
Glass 效果只用于层级表达，不牺牲文字可读性。
动画必须解释状态变化，例如生成、确认、编辑、拒绝、完成。
尊重 Reduce Motion；如果当前项目尚未接入无障碍偏好，先预留 TODO。

9. 下一步开发建议
现在最值得做的是：后端环境变量 + DeepSeek provider 骨架；并并行建立轻量 UI tokens，不做全局重设计。
原因：后端 provider 骨架能提前建立安全边界，UI tokens 能避免后续样式分散，同时都不会过早改动核心业务流程。
建议改动范围
创建后端环境变量读取方式，例如 DEEPSEEK_API_KEY。
定义统一 AI provider interface，预留 mock/deepseek/future providers。
定义 task draft 输出结构，避免前端直接依赖模型原始响应。
提供最小 curl/manual test，先不强行接入完整 UI。
建立 theme tokens、GlassCard、MotionListItem，但只在一个页面试点。
DeepSeek/Claude Code 执行前必须遵守的 refactor gate
先 inspect 相关文件，不要直接改。
把任务分类为 patch / increment / refactor-first / rewrite-module。
提出最小安全计划。
只实现批准范围，不创建 V2/New 临时重复组件。
最后报告 changed files、每个文件职责、测试命令和剩余风险。
